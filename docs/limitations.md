# 既知の制約

## データモデル

- `disease`は単一スナップショット用で、同一コードの複数版を同時に保持できない。診療行為側は v0.3 で複数改定に対応した。
- 2版を比較したとき、新しい版に無いコードが「廃止された」のか「配布対象から外れた」のかは、配布マスターだけでは区別できない。
- 同一コードの突合だけでは、制度上の点数変更を追えない。旧コードを廃止して新コードを追加する形で表現された改定は、コード集合の差のほうに現れる。
- 制度項目の軸はチェッカー用JSONの限定した注釈として追加した。SQLの汎用的な制度項目管理や全コードの分割・統合対応は未実装。明示コード集合は編集判断であり、専門家による最終確認は未実施。
- 旧コードと新コードの点数が一致しても、対応関係の根拠にはならない。減算コード同士は同じ所定点数へ同じ係数をかけるため、意味が異なっていても点数は一致する。
- `revision`は診療報酬改定を表すが、傷病名マスター等の個別更新日を保持する`dataset_release`は未実装。
- 区分番号・施設基準の日本語名称には手入力値があり、全件の原典照合が完了していない。
- 移行対応テーブル固有の7列レイアウトは、取得元資料との再照合を継続している。
- 修飾語マスターは集計のみで、DB取込は未実装。

## 判定範囲

- 施設基準テーブルは、届出情報との機械的な一致を試すPoCである。
- 告示、通知、疑義解釈、患者条件、併算定、算定日数などを網羅していない。
- したがって、医療機関の算定可否を判定・保証できない。

## 集計と解釈

- 件数は指定スナップショットに依存し、マスター更新後も維持されるとは限らない。
- コード帯の偏りから採番方針の歴史を推測できるが、運用理由は配布データだけでは確定できない。
- ICD-10への多対一写像は元の粒度を失うが、ICD-10から候補を検索できないという意味ではない。
- 病名×修飾語の単純直積は理論値であり、有効な臨床病名や請求可能な組合せの件数ではない。

## 技術

- 施設別チェッカーは3疾患のⅠ〜Ⅲ・R06→R08の8項目に限定（Ⅱ・Ⅲに未確認対応あり）。施設プロフィールの保存・自動取得、患者条件の入力、影響額の計算はない。制度変更の網羅性を保証しない。
- 初期・急性期・データ提出加算の詳細な年度間要件比較は未収録。コード分割と観測点数を表示するが、要件が不変だとは判定しない。
- 「対象外」は選択区分の登録対応範囲についての表示。施設全体に影響しないという意味ではない。未登録の対応は「要確認」とする。
- 個別改定項目は改定案段階の資料。疾患別の正式通知を追加参照したが、全告示・通知・疑義解釈・経過措置の照合は未完了。予定コード一覧の個別セルは今回は再照合していない。
- 公開JSONは指定マスターの固定スナップショット。件数不一致時はエクスポートを止め、マスター更新に自動追随しない。元CSVハッシュは公開JSONに記録するが、DB内の入力履歴自体は管理しない。
- 静的ページは生成データJSを用いてHTTP(S)・file:///の両方で起動可能。JavaScriptの実行とassetsフォルダを含むファイル一式が必要。直接表示での外部JS実行が組織のブラウザ設定等で禁止される場合はHTTPで開く。根拠PDFの閲覧にはネット接続が必要で、ページ移動はPDFビューアーの対応に依存する。

- pandasで全行をメモリへ読み込むため、より大きいマスターではストリーム処理の検討が必要。
- SQLiteを前提とし、並行更新や複数利用者の権限制御は対象外。
- Windows／cp932入力を主な検証環境としている。

## Ⅱ・Ⅲの未確認事項

初期・急性期・データ提出加算のⅡ・Ⅲ（3疾患×2等級×3項目＝18対応）は追加施設要件の原典照合が未完了のため要確認。コード所属は推定で登録していない。総合計画評価料のⅢは当該届出単独では対象外。他の届出を持つ施設の算定可否は別途確認する。人による最終確認・個別施設の届出照合は全項目で未実施。[対応表](impact-design.md#9区分への拡張2026-09-15)を参照。
